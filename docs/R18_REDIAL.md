# R18 重复拨号保护候选（待实机验收）

用户反馈：接电话的另一部手机拒接后，AirSIM 报错并再次呼叫。用户报告测试版为 R18；本次只读检查的 USB 设备版本文件和运行服务均报告 R17，因此不能把两份信息视为同一次版本验证。没有导出真实号码、通话日志正文或录音。

## 已复现的代码缺口

旧 MU300 后端仅为非空且不变的 operation_id 保留进程内拨号回执。模拟对端拒接、可靠空闲快照结束原通话后，再发送无编号或新编号的拨号请求，旧实现会第二次执行 ATD。测试修改前两种情况均失败，修复后均仅有一次 ATD。尚无现场请求跟踪证明客户端实际使用的是哪一种重试路径；不能把这项复现当作所有触发原因已查明。

## 候选行为与限制

- 在发送 ATD 前，先将拨号保护记录原子保存到私有 mu300-calls/dial.json；失败时不拨号。
- 相同操作编号继续使用原有回执去重；最近一次操作的摘要持久保留，服务重启不把它当新请求。
- 通话结束或未知提交恢复为空闲后，同一号码进入两分钟保护期。即使后续请求换编号、漏编号或改走云端，也不会立即再次拨出。
- 云端命令编号传入 MU300 拨号去重，不再丢弃命令身份。
- **手动向同一号码重拨也必须等两分钟。** 旧客户端请求无法可靠区分自动重试和新的人工意图；这是保守保护，不是完整客户端重试逻辑修复。保护期到期没有任何自动拨号任务。
- 保护记录仅存摘要、时间和状态，不存明文号码或正文；损坏、符号链接或写入失败时阻止新的拨号。
- 固定日志只记录“尝试一次 ATD”或“被保护拦截”，不记录号码、操作编号或请求体，可用于下一次验收区分新请求与实际拨号尝试。

本次保护覆盖最近一次拨出的号码；并不宣称能识别所有跨设备、跨号码或任意延时的客户端自动重试。iOS/Android 客户端、上游工作树保持原样。

## 验证

新增 9 个回归测试，覆盖对端拒接后的无编号/新编号请求、HTTP 连续重试、局域网失败后改走云端、未知结果、并发提交、服务重启、长通话结束、保护期后人工请求，以及损坏/不可写的保护记录。完整隔离 Agent 的 race/vet 已通过。测试使用模拟号码与模拟 AT 传输，没有真实拨号。

R18 Release 暂停，未推送或发布。新候选尚未安装；需在指定设备上安装后，由用户手动拨号、由对端拒接，观察至少两分钟内没有再次响铃，同时核对脱敏拨号计数。该实机测试及安装需要明确安排。
