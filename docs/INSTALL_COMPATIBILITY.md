# 安装兼容性：取消系统与内核版本硬限制

本策略随 v0.1.0-r15 发布。旧 r12 Release 及已安装的 r14 保留原有行为，需要安装新版插件才能使用新策略。

## 取消的限制

| 入口 | 当前源码行为 |
| --- | --- |
| `scripts/install.sh` | 不读取/比较 mu300-linux、OpenWrt 或内核的版本号；不要求版本标记文件存在 |
| 插件“下载并更新” | 移除固定内核及 mu300-linux 两个版本的白名单，检查架构和必要工具 |
| 默认 `prepare` | 移除镜像/内核白名单和旧音频 extra 自动安装分支，复用已安装音频工具 |

不需要 `--force` 或额外环境变量。固件升级导致版本字符串变化，不再成为插件拒绝安装的理由。

默认启动要求能找到 `mu300-at`、`mu300-voice`、`mu300-audio-dsp`。
缺少工具时显示具体依赖提示，请先安装适用于设备的 MU300 控制与音频组件。
包内保留的旧音频依赖供来源追溯，不再由默认启动脚本自动安装。
已有 `/etc/airsim/prepare.local` 优先执行且不会被修改，管理员自定义脚本中的检查仍由该脚本决定。

## 保留的检查

- 当前安装包的 CPU 架构为 aarch64 / aarch64_generic。
- 安装脚本仍要求 APK v3 包格式工具；这是包格式要求，不是 OpenWrt 发行版本锁定。
- 固定下载仓库和目标插件版本、哈希、公钥指纹、APK 签名与已签名包身份校验。
- 线上更新仍只选择较新的插件版本，安装后核对实际版本，不自动降级。
- 通话、媒体和短信空闲检查，以及升级时停止电话服务与并发操作锁。
- 音频上游自身的驱动 ABI 检查。不会设置驱动版本绕过变量或强装内核模块。

取消安装版本限制不等于保证所有系统的通话和音频兼容。已测试环境仍在 README 记录；
新硬件依照 `HARDWARE_ADAPTATION.md` 单独适配和验收。

## 如何获得新行为

从 [r15 Release](https://github.com/kai-wu-cortex/airsim-mu300/releases/tag/v0.1.0-r15)
获取安装脚本、APK、公钥和 SHA256SUMS，按 README 安装。脚本固定下载同版 r15。
已有 r14 的用户也可开启预览频道，检查更新后关闭电话服务并确认升级。
本版不替换旧 Release 文件，不更新系统、音频驱动或客户端。

## 验证范围

回归测试执行真实安装脚本的前置检查片段，确认没有系统版本文件、不能查询内核版本时，
aarch64 和必要工具仍可通过；错误架构、缺工具、不支持 APK v3 时拒绝。
更新器测试确认仅查询 CPU 架构，缺音频工具或无法确认架构时拒绝。
原有签名、包身份、通话/短信空闲及安装失败测试保留。
此次不进行真实拨号、短信发送或音频验收。

本次本地验证通过：插件 `go test -race ./...`、`go vet ./...`，28 项 Node 测试，安装/启动脚本语法及差异空白检查。发布验证与未验收项目见 [r15 发布说明](RELEASE_v0.1.0-r15.md)。未修改 AirSIM 客户端与上游工作树。
